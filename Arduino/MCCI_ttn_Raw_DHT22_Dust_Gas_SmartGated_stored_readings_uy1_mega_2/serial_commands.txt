HOW IT WORKS
------------
- Serial port: 38400 baud (matches Serial.begin(38400) in setup() — set your
  terminal/monitor to the same rate or everything you see is garbage).
- Type a command and end it with '#'. That's the only thing the parser
  looks for — it does not care about line-ending mode (None / NL / CR /
  CR+NL all work; \r and \n are silently ignored as they arrive).
- Commands are only read from inside loop(), i.e. while the device is
  actively awake between sleeps (during the boot burst, every ~90s for the
  first ~13 min; every TX_INTERVAL after that). There's no wake-from-sleep
  path — the UART is unpowered during LowPower.powerDown(), so bytes sent
  while the device is asleep are simply never received, not queued and not
  errored, just silently gone. No echo at all (not even the "Downlink hex:"
  line) after sending a command means this, almost always — not a bug.

  TIMING — how to tell if the window is open:
    - The line "Sleeping <N>s" is the device announcing it's about to call
      lowPower() right now — the awake window is closing the instant you
      see it. Don't bother sending after that line; it won't arrive.
    - The window reopens once the device wakes: right after that sleep,
      you'll see the sensor readout line (T:.../H:.../DUST_ADC:...) and the
      EV_TXSTART / EV_TXCOMPLETE lines as it sends. That whole stretch,
      from wake-up through the TX/RX handling, is your actual window —
      send as soon as you see those lines, not after "Sleeping" reappears.
    - Easiest fix if you keep missing it: send /@I30# (30s is the minimum
      interval) once you do catch a window, or send /@S1# for a one-shot
      1-minute wake — either shortens the asleep stretch a lot, making the
      awake window come around often enough to just send commands normally
      without watching for the exact moment.
- The command buffer is a fixed 24 bytes (SERIAL_CMD_BUFFER_SIZE), so the
  whole command including "/@", the letter, any digits, and the trailing
  "#" must stay under that — every command below is well within it.
- Every command — serial or downlink — prints "Downlink hex: " /
  "Downlink ASCII: " / "Command: " diagnostic lines first. That's the
  shared parser talking, not a leftover radio message; it's normal to see
  those lines even though nothing went over the air.

COMMAND REFERENCE
-----------------
  /@I<secs>#     change TX interval (min 30 s), saved to EEPROM immediately
  /@S<minutes>#  sleep (go silent) for N minutes, one-shot override
  /@T#           request an immediate transmission
  /@P#           downlink: 16-byte status reply on port 2 (unchanged)
                 serial:   verbose local state dump, no radio TX at all
  /@E#           force an immediate EEPROM save (normally batched every
                 20 uplinks) — same effect from either transport
  /@F<7-12>#     change spreading factor (SF7..SF12). Applies to RAM
                 immediately (same as always), and as of 2026-09-09 also
                 arms confirmed-uplink verification: a confirmed Port 2
                 ping fires as soon as the TX path is free (redesigned
                 2026-09-09 from an earlier Port 1 design that never
                 actually verified anything — see the field-diagnostics
                 doc §3.8), and the change only gets written to EEPROM if
                 it comes back ACK'd. No ACK after LMIC's own retry budget
                 (8 attempts internally, ~3s apart — this firmware doesn't
                 loop for it) reverts RAM to the last known-good SF/TXP
                 automatically. /@P# shows "Radio verify requested" while
                 waiting for the ping to fire, then "Radio verify pending"
                 once it's actually in flight.
  /@X<2-20>#     change TX power (dBm). Same confirmed-uplink verification
                 as /@F# above — one shared pending flag, either command
                 arms it.
  /@R#           software restart (watchdog reset); flushes EEPROM first
                 if a write was pending
  /@Z#           factory reset (clear EEPROM, reset counters, restart)
  /@M<0-2>#      switch operating mode:
                   0 = NORMAL          duty-cycled, PMOS-gated, attempts the gas sensor
                   1 = NORMAL_NO_GAS   duty-cycled, PMOS-gated, skips the gas sensor
                   2 = ALWAYS_ON       legacy: both rails on continuously,
                                       60s TX interval by default
                 RAM only unless committed via /@CP# — an uncommitted mode
                 resets to NORMAL on any reset (brownout or /@R). ALWAYS_ON
                 itself is never committable even via /@CP# (see below) —
                 any reset always comes back up in NORMAL or NORMAL_NO_GAS,
                 never ALWAYS_ON, regardless of what was active before
  /@K<hex>#      peripheral keep/kill mask (bit0=DHT22, bit1=dust,
                 bit2=gas, bit3=battery ADC; default 0x0F=all on).
                 Clearing a bit skips that sensor's transaction entirely —
                 e.g. /@K0E# drops DHT22 without touching dust/gas/battery,
                 useful if a shorted 1-wire line is causing blocking
                 timeouts. RAM only unless committed — see /@CP# below.
  /@B#           start a burst at the default 9 frames / 90s spacing (same
                 mechanism as the boot burst)
  /@B<count>,<interval_s>#
                 start a burst with a custom frame count (1-250) and
                 spacing (30-3600 s) — e.g. /@B20,30# for a 20-frame link
                 margin survey at 30s spacing. Interval below 90s is
                 accepted but logged with a brownout warning — 90s is the
                 default specifically because 30s spacing was measured to
                 brown out a solar-only rail at night; fine on USB power,
                 risky on a field node running off battery/solar. NOT
                 saved to EEPROM — one-shot, like /@B#.
  /@W<warmup_s># gas sensor warmup threshold (10-3600 s, default 300).
                 Backs both gas_getADC()'s own "is this reading warmed up
                 yet" check and regime B's off-sleep scheduling (TX_INTERVAL
                 >= 600s in MODE_NORMAL) from the same value, so shortening
                 it actually speeds up reporting instead of just changing
                 when the node claims to be ready. If the new warmup segment
                 (warmup + 60s margin) reaches or exceeds TX_INTERVAL in
                 regime B, the off-sleep phase floors at 0 and the cycle
                 stretches to the warmup segment's length instead of holding
                 TX_INTERVAL — logged as a warning, not silently absorbed.
                 RAM only unless committed — see /@CP# below.
  /@N<count>#    autonomous Port 2 status-frame ratio (1-250, default 10) —
                 sends a status frame (same payload as /@P#'s downlink form)
                 every <count> successful Port 1 uplinks, so reset reason/
                 mode/battery stay visible without polling. Only counts
                 real Port 1 telemetry — the lowBatteryMode heartbeat (which
                 sends status frames on Port 2 every cycle already) doesn't
                 feed this counter. Changing the ratio restarts the count
                 from 0. RAM only unless committed — see /@CP# below.
  /@CP#          commit current mode/sensor-mask/gas-warmup/ping-ratio/
                 battery-thresholds to EEPROM as the boot profile (Commit
                 Parameters). Restored on every boot from here on until the
                 next /@CP# or a /@Z# factory reset clears it. Committing
                 while in ALWAYS_ON saves NORMAL instead — ALWAYS_ON is
                 never persisted, since that would reintroduce the
                 brownout-loop risk g_mode being RAM-only by default was
                 designed to prevent. Burst count/interval (/@B#) are
                 deliberately NOT part of this command — they stay
                 RAM-only/one-shot regardless.
  /@V<low>,<rec>,<crit>,<psave>,<psaveRec>#
                 battery guard thresholds (raw ADC, 6-439 each). Must
                 satisfy CRITICAL < LOW < POWERSAVE < RECOVER <=
                 POWERSAVE_RECOVER (that last relation allows equality —
                 the rest don't). Field-tuned defaults: LOW=335, REC=360,
                 CRIT=315, PSAVE=350, PSAVE_REC=380. Violating the ordering
                 isn't just a bad tuning choice — CRITICAL>=LOW silently
                 disables the heartbeat-skip check, RECOVER<=LOW collapses
                 that ladder's hysteresis to zero, and POWERSAVE<=LOW makes
                 power-save mode unreachable on the way down. RAM only
                 unless committed — see /@CP# above.

NOTES
-----
- /@P# is the one command whose behavior genuinely differs by transport:
  over a downlink it still sends the compact 16-byte port-2 status frame
  exactly as before (see payload.txt / ThingsBoard_RuleChain.md §8); over
  serial it never touches the radio and instead prints everything above,
  free of LoRaWAN's airtime/payload-size limits.
- /@E# does not reset TX_INTERVAL to the firmware's compiled-in default —
  it only flushes whatever is currently live to EEPROM. To force a fresh
  firmware's default interval to actually take over after a reflash (since
  a normal USB upload never touches EEPROM), send /@Z# once, or send a
  fresh /@I<value># with the interval you want.
- /@M<0-2># is never persisted to EEPROM — this is deliberate, not a gap.
  Any reset, whether a real brownout or a /@R restart, boots back into
  NORMAL regardless of what mode was active before, so a forgotten node
  can't stay in ALWAYS_ON's dense/full-power cadence indefinitely across a
  power cycle. If you want ALWAYS_ON again after a reset, send /@M2# again.
- Entering ALWAYS_ON overrides TX_INTERVAL with its own 60s default and
  remembers whatever interval was active before; leaving ALWAYS_ON (send
  /@M0# or /@M1#) restores that remembered value. Sending /@I<secs># while
  already in ALWAYS_ON changes the interval for the rest of that session,
  same as any other mode — it doesn't change what gets restored afterward.
